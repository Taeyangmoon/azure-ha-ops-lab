# 모듈 4. 비용 (5분)

[← 모듈 3](03-alert-autoscale.md) | [다음: 정리 →](05-cleanup.md)

## 학습 목표

- Microsoft Cost Management에서 **예산**을 만들어 초과 전에 알림을 받는다.
- **태그**별로 비용을 나눠 본다.

> **참고**: 비용 데이터는 사용 후 **8~24시간** 뒤에 나타납니다. 방금 만든 리소스는 아직 안 보일 수 있습니다. 비어 있어도 정상이며, 화면 구성과 사용법을 익히는 것이 목표입니다. 필요한 권한: 구독 또는 리소스 그룹에 대한 **Cost Management Contributor** (또는 Owner/Contributor).

## 1단계. 예산 만들기 (3분)

1. Azure 포털에서 **Cost Management** → **예산** → **+ 추가**
2. 범위(Scope): 리소스 그룹 `rg-ha-ops-lab` 선택 (구독 전체가 아니라 이 랩만 제한)
3. 이름: `budget-halab`, 기간: 월간, 금액: `10` (통화는 구독 기준)
4. **경고 조건**:
   | 유형 | 비율 | 이메일 |
   |---|---|---|
   | 실제 | 80% | 내 이메일 |
   | 예측 | 100% | 내 이메일 |
5. **만들기**

> 예산은 **지출을 막지 않습니다.** 임계값을 넘으면 알림(또는 작업 그룹 호출)만 합니다. 자동으로 리소스를 멈추려면 작업 그룹에 Automation 등을 연결해야 합니다.

## 2단계. 태그별 비용 분석 (2분)

모듈 0에서 모든 리소스에 `project=azure-ha-ops-lab`, `env=workshop` 태그를 붙였습니다.

1. **Cost Management** → **비용 분석**
2. 범위: 리소스 그룹 `rg-ha-ops-lab`
3. **그룹화 기준(Group by)** → **태그** → `project`
4. **리소스 유형**으로도 그룹화해 어떤 서비스가 비용을 만드는지 비교합니다. (예상: Virtual Machines가 가장 큼, 그다음 Load Balancer, Log Analytics)

데이터가 아직 없다면 범위를 구독으로 올리고 날짜를 **지난 7일**로 바꿔 화면 구성을 살펴보세요.

## 생각해 볼 점

- 태그가 없다면 "이 비용이 누구의 것인가"를 어떻게 알 수 있을까요? → 환경, 팀, 프로젝트별 태그 정책이 중요합니다.
- 자동 크기 조정의 **최대 인스턴스 수**는 비용의 상한선이기도 합니다.
- Log Analytics는 수집한 **데이터 양(GB)** 으로 과금됩니다. 수집 규칙(DCR)을 필요한 것만 수집하도록 설계하는 이유입니다.
